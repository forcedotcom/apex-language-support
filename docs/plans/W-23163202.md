# W-23163202 — Testbed adopts SDK, deletes ApexJsonRpcClient

## Context

- `apex-lsp-testbed` uses own 1277-line untyped `ApexJsonRpcClient` in `src/client/ApexJsonRpcClient.ts`
- 16 files reference `ApexJsonRpcClient` across testbed src + tests
- SDK (`@salesforce/apex-lsp-client`) exposes `createHeadlessClient` + `ApexClientCore` with typed methods, middleware, lifecycle
- SDK's `createNodeStdioConnection` replaces testbed's child-process spawn logic
- Testbed currently has NO dependency on `@salesforce/apex-lsp-client` in package.json or tsconfig references
- Key consumers to migrate: `clientFactory.ts`, `serverFactory.ts`, `LspTestFixture.ts`, `cli.ts`, `mockServer.ts`, `webLanguageServerHarness.ts`, integration tests

### SDK actual public API (ApexClientCore)

`ApexClientCore` exposes these public methods (source: `packages/apex-lsp-client/src/apexClientCore.ts`):
- Lifecycle: `initialize(settings, params?)`, `shutdown()`, `dispose()`, `isDisposed()`
- Generic RPC: `request<R>(method, params?)`, `notify(method, params?)`
- Typed LSP: `hover(params)`, `completion(params)`, `definition(params)`, `documentSymbol(params)`
- Typed apex/*: `sendWorkspaceBatch`, `processWorkspaceBatches`, `workspaceLoadComplete`, `workspaceLoadFailed`, `queueState`, `graphData`, `profilingStart`, `profilingStop`, `profilingStatus`
- Handlers: `onFindMissingArtifact`, `onRequestWorkspaceLoad`, `onWorkspaceIngestionComplete`, `onQueueStateChanged`
- Middleware: `use(mw): Disposable`

**NOT in SDK**: `openTextDocument`, `closeTextDocument`, `isHealthy`, `waitForHealthy`, `getServerCapabilities`, `start`, `stop`. Tests need these; testbed-local wrapper required.

### SDK lifecycle model vs testbed's current model

- **Testbed (ApexJsonRpcClient)**: `new ApexJsonRpcClient(opts)` then `client.start()` (spawns + initialize + waitForHealthy), `client.stop()` (shutdown + exit + kill)
- **SDK (createHeadlessClient)**: `createHeadlessClient(serverPath, opts)` returns `{ core, connection, process }` — spawns + creates core + calls `connection.listen()`. Caller then calls `core.initialize(settings)` separately. Shutdown: `core.shutdown()` then `core.dispose()`.
- These are fundamentally different: SDK separates spawn from initialize; there is no single `start()` call.

### SDK middleware model vs testbed's current model

- **SDK (`ApexClientMiddleware`)**: intercept-based with `next` continuation. Optional methods: `sendRequest?(method, params, next)`, `sendNotification?(method, params, next)`, `onRequest?(method, params, next)`, `onNotification?(method, params, next)`. Registered via `core.use(mw)`.
- **Testbed (`RequestResponseCapturingMiddleware`)**: patches `connection.sendRequest` by replacing the function reference. `installOnClient(client)` replaces `client.sendRequest` with a wrapper.
- Migration: rewrite capturing middleware to implement `ApexClientMiddleware.sendRequest` with `next` continuation, storing method/params/response. No more function patching.

### Phase 2 — Create ApexLspTestClient wrapper + MockRpcConnection

This phase creates the testbed-local abstractions needed before factory migration.

#### 2a — ApexLspTestClient (convenience wrapper around ApexClientCore)

Create `packages/apex-lsp-testbed/src/test-utils/ApexLspTestClient.ts`:
- Wraps an `ApexClientCore` instance (composition, not inheritance)
- Adds the convenience methods tests depend on that SDK intentionally omits:
  - `openTextDocument(uri, text, languageId?)`: sends `textDocument/didOpen` via `core.notify`
  - `closeTextDocument(uri)`: sends `textDocument/didClose` via `core.notify`
  - `isHealthy()`: returns `!core.isDisposed()` (simplest contract; SDK has no server-health RPC)
  - `waitForHealthy(timeoutMs)`: polls `isHealthy()` with backoff up to timeout
  - `getServerCapabilities()`: returns the `InitializeResult.capabilities` captured during `initialize`
- Delegates typed LSP methods directly: `hover`, `completion`, `documentSymbol`, `definition` pass through to `core`
- Delegates generic RPC: `request`, `notify` pass through to `core`
- Lifecycle: constructor accepts `ApexClientCore`; `dispose()` delegates to `core.dispose()`

#### 2b — MockRpcConnection (in-memory RpcConnection for demo mode)

Create `packages/apex-lsp-testbed/src/test-utils/MockRpcConnection.ts`:
- Implements `RpcConnection` (`sendRequest`, `sendNotification`, `onRequest`, `onNotification`, `onError`, `onClose`, `dispose`, `isListening`)
- `sendRequest(method, params)`: dispatches to registered mock handlers by method name; returns mock responses for `textDocument/hover`, `textDocument/completion`, `textDocument/documentSymbol`, `textDocument/formatting`, `initialize`
- `sendNotification(method, params)`: handles `textDocument/didOpen`, `textDocument/didChange`, `textDocument/didClose` by updating in-memory document store
- `onRequest`/`onNotification`: stores handlers, returns Disposable
- `isListening()`: returns false until `listen()` called (satisfies `ApexClientCore.create` precondition)
- `listen()`: sets listening flag to true
- This replaces `MockApexJsonRpcClient` entirely. Demo mode creates: `const mockConn = new MockRpcConnection(); const core = await ApexClientCore.create(mockConn); mockConn.listen(); const client = new ApexLspTestClient(core);`

#### 2c — Update ServerTestContext type

- `ServerTestContext.client` type becomes `ApexLspTestClient` (NOT raw `ApexClientCore`)
- Tests continue calling `client.openTextDocument(...)`, `client.isHealthy()`, `client.hover(...)` unchanged
- Files: `packages/apex-lsp-testbed/src/test-utils/ApexLspTestClient.ts` (new), `packages/apex-lsp-testbed/src/test-utils/MockRpcConnection.ts` (new), `packages/apex-lsp-testbed/src/test-utils/serverFactory.ts` (type update)

### Phase 5 — Migrate test-utils (LspTestFixture, middlewares)

#### 5a — Rewrite RequestResponseCapturingMiddleware as ApexClientMiddleware

Rewrite `RequestResponseCapturingMiddleware` to implement `ApexClientMiddleware`:
- Implement `sendRequest(method, params, next)`: capture request start, call `next(params)`, capture response/error, record `RequestResponsePair`, return result
- Implement `sendNotification(method, params, next)`: capture notification, call `next(params)`
- Remove `install(connection)` (patches MessageConnection) — no longer needed
- Remove `installOnClient(client)` (patches arbitrary object) — no longer needed
- Registration: callers use `core.use(capturingMiddleware)` which returns a `Disposable`
- Keep query methods unchanged: `getCapturedRequests()`, `getCapturedRequestsByMethod()`, `getLastCapturedRequest()`, `clearCapturedRequests()`

#### 5b — Rewrite NotificationCapturingMiddleware as ApexClientMiddleware

- Implement `onNotification(method, params, next)`: capture incoming notification, call `next(params)`
- Remove `installOnClient(client)` — registration via `core.use(notificationMiddleware)`

#### 5c — Rewrite LspTestFixture to use ApexLspTestClient + SDK middleware

- Constructor: accepts `serverPath` + options. Internally calls `createHeadlessClient` + `core.initialize()` + wraps in `ApexLspTestClient`
- `setup()`: `createHeadlessClient` then `core.initialize()`, then `core.use(this.capturingMiddleware)` (registers via SDK middleware chain)
- `teardown()`: dispose middleware registration (via returned Disposable), then `core.shutdown()` + `core.dispose()`
- `executeTestStep()`: uses `client.isHealthy()` and `client.request(step.method, step.params)` (both delegate through `ApexLspTestClient` to `core`)
- Files: `packages/apex-lsp-testbed/src/test-utils/LspTestFixture.ts`, `packages/apex-lsp-testbed/src/test-utils/RequestResponseCapturingMiddleware.ts`, `packages/apex-lsp-testbed/src/test-utils/NotificationCapturingMiddleware.ts`
