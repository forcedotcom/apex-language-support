# W-23163195 — LanguageClientConnection adapter

## Context

- `ApexClientCore` talks to transports via `RpcConnection` port
- `JsonRpcConnection` (W-23163187) already wraps `vscode-jsonrpc` `MessageConnection`
- Extension's `language-server.ts` has 2 inline `ClientInterface` impls (web + desktop) wrapping `BaseLanguageClient` — ~500 lines of duplicated boilerplate
- Create `LanguageClientConnection` adapter in `apex-lsp-client/src/transports/` that wraps `BaseLanguageClient` to satisfy `RpcConnection`
- Key bridging concerns:
  - `BaseLanguageClient.sendRequest` accepts optional `CancellationToken` — port omits it (see Cancellation decision below)
  - `BaseLanguageClient.onRequest` returns `Disposable` (matches port; `ClientInterface.onRequest` returns void)
  - `BaseLanguageClient` has no `onError`/`onClose` — use `onDidChangeState` to synthesize `onClose` when state transitions to `Stopped`
  - `BaseLanguageClient` owns the LSP lifecycle (`start()`/`stop()`) — adapter's `dispose()` calls `stop()`
  - `isListening()` maps to `isRunning()`

### Cancellation decision

`RpcConnection.sendRequest` is token-free by design (see `rpcConnection.ts` l.42-46).
`ApexClientCore` never passes a `CancellationToken` and has no internal cancellation
semantics — all requests are fire-and-wait. `BaseLanguageClient.sendRequest(method,
params, token?)` accepts an optional token, but when omitted the underlying
`vscode-jsonrpc` layer simply never sends `$/cancelRequest`, which is safe and
spec-compliant (LSP cancellation is cooperative and optional).

Conscious tradeoff: this adapter does NOT support request cancellation via
`CancellationToken`. If a future WI adds cancellation to `ApexClientCore`, the
port signature and adapter would both need extending. Acceptable because:
(a) no current caller requires it, (b) extension's existing `ClientInterface`
impls also never propagate cancellation tokens from `ApexClientCore`, and (c) the
`RpcConnection` port is versioned inside this SDK and can be extended additively.

The adapter's JSDoc will explicitly document this limitation.

## Phases

### Phase 1 — LanguageClientConnection adapter

- Add `vscode-languageclient` as peer dep in `apex-lsp-client/package.json`
- Create `src/transports/languageClientConnection.ts`
  - Implements `RpcConnection`
  - Constructor takes `BaseLanguageClient`
  - `sendRequest` → delegates without token; JSDoc: "CancellationToken is intentionally
    omitted — the RpcConnection port is token-free. See plan Cancellation decision."
  - `sendNotification` → delegates
  - `onRequest` → delegates, returns `Disposable`
  - `onNotification` → delegates, returns `Disposable`
  - `onError` → subscribe `onDidChangeState`, emit Error on `Stopped` (unexpected)
  - `onClose` → subscribe `onDidChangeState`, fire on transition to `Stopped`
  - `isListening()` → `client.isRunning()`
  - `dispose()` → `client.stop()`
- Export from `src/index.ts`

Commit: `feat(client): LanguageClientConnection adapter wrapping BaseLanguageClient - W-23163195`

### Phase 2 — Unit tests

- Create `test/transports/languageClientConnection.test.ts`
- Mirror `jsonRpcConnection.test.ts` structure:
  - Mock `BaseLanguageClient` (sendRequest, sendNotification, onRequest, onNotification, isRunning, stop, onDidChangeState)
  - Verify 1:1 delegation for send*, on* methods
  - Verify `onError`/`onClose` fire on state change to Stopped
  - Verify `isListening()` maps to `isRunning()`
  - Verify `dispose()` calls `stop()`

Commit: `test(client): LanguageClientConnection unit tests - W-23163195`

### Phase 3 — Integration test exercising LanguageClientConnection

- Create `test/integration/languageClientConnection.integration.test.ts`
- Follows same gated pattern as `headlessHost.integration.test.ts` (requires
  `RUN_INTEGRATION=1` and the server binary at `apex-ls/dist/server.node.js`)
- Uses a `LanguageClient` (from `vscode-languageclient/node`) configured with a
  stdio `ServerOptions` pointing at the real server binary; supplies a minimal
  `LanguageClientOptions` with in-memory document selector
- Wraps the `LanguageClient` in the new `LanguageClientConnection` adapter
- Creates `ApexClientCore` on that adapter
- Performs the full LSP initialize handshake via `core.initialize()`
- Asserts:
  - `initResult.capabilities` is defined (proves adapter round-trip works)
  - `connection.isListening()` returns `true` while running
  - `core.shutdown()` + `core.dispose()` complete without error
  - After dispose, `connection.isListening()` returns `false`
- Proves adapter code path end-to-end against real server, not just
  mocked delegation

Commit: `test(client): LanguageClientConnection integration test - W-23163195`

### Phase 4 — Export from browser entry + docs

- Export `LanguageClientConnection` from `src/browser.ts` (usable in both contexts)
- Update `src/index.ts` JSDoc to mention the new adapter

Commit: `chore(client): export LanguageClientConnection from browser entry - W-23163195`
